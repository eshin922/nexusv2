═══ Additional Q — do Nexus-authored leaves arrive in NS unpriced? ═══

  Trace of Nexus's HubSpot Product create flow
  (src/lib/hubspot-mapper.ts:106-117, called from src/app/actions/leaves.ts):

    mapLeafToHubspotCreate({name, sku?, unitCost?, url?})
      → HubSpot Product { name, hs_sku?, hs_cost_of_goods_sold?, hs_url? }

  Line 20 of hubspot-mapper.ts is explicit:
    | price  | (no column)  | (skip)  | sell-price lives on quote_skus, not leaves |

  Nexus does NOT set 'price' on the HubSpot Product create. Only cost
  (hs_cost_of_goods_sold), NOT sell-price. And Nexus never touches
  NetSuite's REST /price endpoint at leaf creation.

  The HubSpot → NetSuite sync path (whatever bidirectional connector
  DPS uses — OpsHub or similar) is outside Nexus's control. Whether
  that connector defaults a $0 price on NS-side item creation
  depends on its own field-map config. From SuiteQL evidence:
    - 89 of 1350 active items are priced (7%). Most items in the
      account (1261 / 93%) are unpriced.
    - This ratio suggests the sync pipeline does NOT set a default
      price at item creation.

  Implication for the trickle:
    Every new leaf a PM creates via AddProductModal → HubSpot →
    NS sync arrives in NetSuite unpriced. Vu's bulk update fixes
    today's catalogue; the same query will need to run periodically
    unless one of the following lands:
      (a) The HubSpot → NS sync config is updated to default $0.00
          price at item creation (Ops-Hub-side change, not Nexus)
      (b) Nexus adds a post-create hook that PATCH-sets $0.00 on
          the newly-created NS item (adds NS API call to the leaf
          create flow — requires Nexus to know the NS item id
          post-sync, which depends on sync latency + surface access)
      (c) A scheduled Nexus job that periodically scans for
          unpriced items and PATCH-sets $0.00

  Option (a) is cleanest — sync-tool config is where "default at
  creation" belongs, not application code. Option (b) races the
  sync latency. Option (c) is a stopgap.
