# Vendor purchase-order specifications — sandbox

The preferred sandbox template is `DPS Purchase Order` (ID 400,
`CUSTTMPL_TVN_PF_PURCHASE_ORDER`). Its source was downloaded from the signed-in
NetSuite sandbox on 2026-10-06 as
`dps-purchase-order.sandbox-original.xml` (version 158). That saved source
already contains an `NX-SPEC-PROTOTYPE` row inside the item loop, immediately
after each ordinary item row. No template change was saved during inspection.

`dps-purchase-order.sandbox-candidate.xml` preserves the complete template and
changes only the prototype's `${specLine}` to `${specLine?html}`. This escapes
user-entered spec text before embedding it in the XML/PDF. It was saved to the
preferred sandbox template as version 159. The other layout, legacy header
specifications, prices, totals, terms, and addresses are intact.

`dps-purchase-order.quote-theme-v2.xml` is the current quote-aligned design,
generated by `node netsuite/templates/build-quote-theme-v2.mjs`. It uses the
original DPS logo and legal terms, the quote's two-column party layout and
item table, and ordered specifications directly beneath each item. It omits
the original standalone Production Details section because those details are
now supplied by the item specifications. The earlier `quote-theme.xml` is a
superseded design exploration.

The current design is saved as version 6 of sandbox template ID 607, **DPS
Purchase Order — Nexus Quote Design (Sandbox)**. It is not preferred; the
original template 400 remains preferred. NetSuite's built-in five-page sample
PDF rendered without address or header overlap and with a prominent Purchase Order heading, the original logo, item-level
specifications, and legal terms. A separate nonpreferred sandbox form (ID 341)
uses this template. PO3676 (internal ID 365143) was printed through that form
with its real vendor, four item lines, three distinct per-line specifications,
and $2,000 total. The actual values exposed literal `br` tags in specification
text; version 6 converts those tags to printed line breaks before escaping
the text. The PO's original form 218 was restored after the print check.
The earlier `purchase-order-line-spec.fragment.ftl` is an alternative compact
layout, not the currently saved sandbox layout.

Both required sandbox transaction-line fields exist: `custcol_nx_ordered_spec`
(record link, applied to sale and purchase items) and `custcol_nx_spec_text`
(Text Area, applied to purchase items). The latter is marked as a sandbox
prototype. The sandbox PO-creation script has been updated and exercised with
two vendors, repeated SKUs with distinct specs, a no-spec line, and a copied
line whose inherited spec link is intentionally not printed. Live PO UI fields
were verified; the alternative's built-in PDF preview is a layout check.

Before the alternative is used for vendor POs:

1. Check that `fm_actives` and its test marker are absent from PO fields,
   template output, PDFs, and logs.
2. Verify ordinary PO creation and ongoing SO-to-PO sync before changing any
   preferred-template setting.
