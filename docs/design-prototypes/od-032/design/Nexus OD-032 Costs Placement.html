OD-032 · Costs placement round trip · no implementation

Where these charges live on the Costs page we already have

Three owner types now exist. This decides where each renders on the shipped V1 Costs page — not what an ideal Costs page would look like. That question belongs to the post-V1 redesign, and every compromise made here is recorded as an input to it.

Answer

Owner-grouped rows, in place

Not a dedicated region. A charge renders where its owner already lives, so no row moves between regions and no section is created.

Disruption

Nothing moves

Production keeps its charges. Freight keeps duty and customs. Tier geometry is untouched in both regions.

Recorded for later

Five V1 compromises

Written down in §05 so they arrive as inputs to the post-V1 redesign rather than as accidental permanent architecture.

01 · the question, narrowed

The page is not up for redesign. Only the placement is.

The earlier stop found that this bundle never draws the Costs region, and that the layout document it amends describes a page that was never built. Both remain true. The response is not to design that page now — a dedicated post-V1 redesign will reconsider Packaging, Production, Freight, landed costs and all three charge owners as one system.

So the question this answers is “where can these charges live clearly and correctly in the existing V1 Costs page?” — and explicitly not “what should the ideal future Costs page look like?”

03 · the decision

A charge renders where its owner already lives

The instruction asks for an explicit choice between a dedicated region, owner-grouped rows inside existing regions, or another layout. This is the second, and the rule above is what makes it more than a convenience: the owner is a commercial object that already has a place on this page, so putting its charges anywhere else would separate a cost from the thing that caused it.

No row moves between regions, and no region is created. That is the whole disruption budget spent: one attribution line in Production, one nested block in Packaging.

Laying it across the tier columns would invite reading it as a rate that scales — the arithmetic phase 2 spent its falsifications proving does not happen.

05 · compromises, recorded

What V1 accepts, so the redesign inherits it as a question

Each of these is a live consequence of optimising for minimum disruption. None is a defect, and none should be read later as a decision about what the page ought to be.

# The compromise Why V1 accepts it, and what the redesign should ask
C1 One-time charges stay split across two regions. Item Group charges in Production, component charges in Packaging. The layout document wants them gathered into one section at the foot. Gathering them now would move rows out of a certified region for a layout nobody has drawn. The redesign should decide whether one-time charges are a family that reads better together than beside their cause.
C2 Duty and customs stay in Freight. The “landed” grouping §7 asks for does not exist. Moving them is a Freight change, which Phase 3 excludes, and they are not charges under this model — they are freight economics. The redesign should decide whether “landed” is a region or a reading.
C3 Project setup has two owners, split by age. The existing setupFeeTotal population is Item-Group-owned; a newly authored Project setup charge would be quote-owned. Both are honest about their own storage: the existing rows are stored against an assembly and BV-012 governs them. The redesign should decide whether Project setup is ever really quote-owned, or whether the vocabulary entry is the thing that is wrong.
C4 There is no Project region. A genuinely quote-caused charge would have nowhere to render. Nothing qualifies, and the V1 sheet offers only component types — so the state is unreachable rather than unhandled. Guard: if a quote-owned type is ever added to the sheet, this region must exist first.
C5 Production’s attribution line is the only signal that grouping is by owner. One region states its owner; the other implies it by nesting. Two regions, two structures, two treatments — consistent within each, not with each other. The redesign should decide what owner attribution looks like as one grammar across the page.
06 · what this does not touch

The boundaries this placement keeps

No anchor is surfaced

Neither owner read consults the anchor leaf. The Item Group comes from the key its economics are stored under; the component from a real FK. owner_ref is read by neither, and OD-028 stays post-gate.

No economics move

This is placement only. No amount, markup, margin or recovery changes, and the customer document is untouched — recovery moves economics, presentation never does.

Tier geometry preserved

Both regions already carry the tier grid at fixed x-positions, and neither addition disturbs a column. The nested charge block sits below the grid, not inside it.

Recovery stays in Pricing

Charges arrive unplaced and the row says so. Placement is elected in Commercial Recovery, per instance — asking here would fuse the two decisions the model keeps apart.
